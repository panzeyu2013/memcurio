# @memcurio/dsh-plugin 记忆可视化插件设计 v1

> 状态：设计基线（2026-09-05，第十六轮讨论结论）。本文是 S0 spike / M0 / M1 / M2 的验收基准；实现与设计背离时以本文为准修订。
> 配套背景：第十五轮单宿主收敛（fea0fa9/83c01dd）后，仓库即 `@memcurio/dsh-plugin` 单包；本设计为该包的"客户端半侧（记忆工作台）+ host 服务层"里程碑。

## 1. 背景与目标

- DSH 上游提供一等第三方浏览器扩展缝：插件包声明 `dsh.client` → host 把其 `./client` bundle 经 `/plugins` 惰性服务；浏览器半侧在冻结模块表（React/Cordis）上运行；**模型永远看不到 UI**（浏览器内核件）。官方 UI 包均以"客户端 `inject` api-remote/controller"与 host RPC（spike 验证第三方等价物）。
- 目标：在 DSH Web 内为当前/各工作区提供记忆工作台——注入面、持久面、状态面 + 记忆生命周期时间线；把被删除 CLI 的运维语义内化为 host 服务；一切记忆变更走"对话即写面"。
- Codex 对照（调研结论）：Codex 至今无一等记忆管理 UI（issue #30299 公开诉求与本设计重合）；phase-2 状态 opaque；usage 遥测不展示；无写路径收据（#41711）；本设计在这些缺口上做出显式答案。

## 2. 总体架构（三层一缝）

```
DSH Web（浏览器）
  client 半侧（dsh.client bundle）：记忆工作台（三面一轴 + 意图启动器）
    │  ① 只读 introspection / 事件推送 delta（host 投影，脱敏）
    │  ② 意图草稿（不直接写；见 §4）
    ▼
host 半侧（同包 node）
  现有插件（事件接线/注入/工具/ctx.llm 通道）
  + Services 层：读服务 / 投影器 / 意图草稿服务（不落库）
    │  ③ 现有调用面（api.ts / engine / core）
    ▼
引擎与存储（SQLite + memory/*.md；零新写路径）
```

设计纪律：
1. **UI 永不静默写记忆**（§4 铁律）；一切持久化变更必须是可见对话动作。
2. 服务层只做"编排 + 脱敏 + 投影"，不发明新语义；每个读/写能力映射到已验证的引擎函数。
3. 浏览器只见服务端脱敏/注入过滤后的数据；写意图不经模型侧不执行。
4. 推送 delta 与快照同源同脱敏。

## 3. 入口（双入口 + 回退预案）

- **设置页**（settings 域，`settings.section` 槽位）：激活与配置——scope、injectContext/registerTools、injectBudgetTokens、provider/model 固定、工作台入口开关。
- **会话标题栏功能入口**：当前工作区"记忆工作台"按钮 → 全宽工作台视图（spike 验证第三方标题栏槽位）。
- **回退预案（已接受）**：若标题栏无第三方槽位 → 设置页直达 + 会话内 `/memory` 斜杠命令唤起工作台。
- 工作台默认绑定当前会话 workspace 的 store；内部提供**跨工作区只读切换**（隔离规则不变，写意图只对当前 workspace 有效）。

## 4. 写语义：对话即写面（铁律 + 规范）

### 4.1 铁律

任何持久化记忆变更（remember/修正/删除/整合触发）都必须是**可见的对话动作**：UI 只生成"意图草稿"（预填用户消息，可编辑），提交后走正常对话流 → 模型经既有工具（`memory_remember` 等 defineTool 工具）执行 → 以标准工具卡出现在会话历史 → 工作台状态面出现审计收据。UI 不提供绕过对话的直接写路径（无浏览器直写、无静默 host 写）。

理由：remember/forget 在文件层同为"对 MEMORY.md/rollouts 的一次文本编辑"，差异只在用户心智框架；对话流使二者共享同一意图管线，且变更天然可见、可审、可回放——满足"像正常 tool call 一样插入对话历史"的要求，且注入扫描/脱敏/出处校验全部留在既有链路上。

### 4.2 意图表达

| 意图 | UI 表达 | 落地 |
|---|---|---|
| "这条重要，要记住" | 持久面条目/时间线节点上的动作 → 预填草稿（引用条目与来源）→ 用户编辑后提交 | 对话流 → `memory_remember` 工具卡 → 收据 |
| "这条过时/没用了" | 同上（修正措辞模板，引用 rollout/块） | 对话流 → agent-only forget/update 语义或整合 agent 的 diff 清理；**无静默删除** |
| 视图收藏（"我常回看"） | 条目卡 ⭐ = **纯 UI 本地标记**（不写记忆；可后续映射 usage 语义） | 视图层状态 |
| 直接改文本 | 工作台提供"打开文件位置/查看原文件"（原生 read 路径）；不做富文本在线编辑 | 用户真源编辑（codex 精神：MEMORY.md 可手编，整合 diff 折入） |
| 硬删除（purge） | M2 才考虑"干跑预览 → 确认"专家路径，且产生对话/审计收据 | 暂不进入 M0/M1 |

### 4.3 可见性与收据

- 变更在会话史有因果（哪个会话、哪个意图、哪个工具调用）；工作台状态面/时间线有审计行可回链（DSH 客户端定位能力 spike 验证；不可用则显示会话/消息引用文本）。
- 每个写服务（即使仅生成草稿）不落库；草稿提交后的执行与失败都在对话流可见（工具卡含参数摘要与结果/错误）。

## 5. UI 信息架构：三面 + 时间线

- **注入面**：当前静态上下文 + 最近注入命中的实时预览（预算条/脱敏态）；**注入模拟器**（任意 query → top-8 命中+来源+blocked 计数+脱敏预览+预算）为 M0 核心。
- **持久面**：Task Group 与 rollout 双层列表（来源/日期/cwd/updated_at/usage_count/last_usage），检索框，"memory days"式新鲜度索引；条目卡含 ⭐（收藏）与意图动作。
- **状态面**：durable queue（pending/blocked/dead/attempts）、worker 路由（request/header 跟随）、自动整合冷却/退避与最近结果、审计流（收据）。
- **时间线轴**：预注入 → 命中 → 原生读取 → 引用 → 证据 → compaction 剪除 → 整合落库，串成因果链；"记忆变更"节点回链来源。

## 6. 实时性（M0 即推送）

host 半侧已订阅全量 session 事件；Services 层投影器输出脱敏增量并推送浏览器：
证据窗口变化、queue 计数、`tools/result` 命中的 usage 跳动、pre-step 注入内容/预算、compaction 配对与 shadowedSeqs 剪除、rollout 落库/整合完成。
连接恢复后先推一次全量快照作为降级兜底；推送通道不可用时回退轮询（1–3s）仅作次级路径。

## 7. host 服务契约（草案）

| 类别 | 服务 | 对应现有实现 |
|---|---|---|
| 上下文 | store.resolve(当前 session)/workspace 列表/隔离告警 | plugin sessions/scope、api.ts |
| 读 | 树/列表/详情/检索（脱敏+注入过滤+分页） | api.ts 六函数、core/read |
| 注入面 | 静态/动态上下文预览、注入模拟器 | engine.buildStatic/DynamicContext、searchMemory |
| 用量 | usage_count/last_usage、原生 read 命中流 | db stage、engine 遥测 |
| 状态 | queue 计数/attempts/blocked、路由、整合冷却 | integrationStatus、db、meta 键 |
| 证据/时间线 | 会话证据窗口、compaction 配对、seed 重放状态 | adapter 内存态、session events |
| 审计 | 记录浏览（收据面） | db audit |
| 意图草稿 | 预填消息合成（不落库） | 纯服务层 |

（写服务在"对话即写面"下不直接暴露为 UI 可调接口；M1 若出现"高级干跑"路径再按既有门禁+审计单列。）

## 8. 安全边界

- 只读数据服务端脱敏/注入过滤后出网；写意图不直接执行。
- UI 是浏览器内核件：不经模型、不进 prompt、不进证据、不进抽取。
- 跨工作区只读浏览不改变任何写语义；意图草稿始终绑定当前会话 workspace。

## 9. 阶段路线与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| S0 spike | ①第三方 `dsh.client`：设置页 section 槽位、标题栏入口（或确认回退 `/memory`）、host remote/推送通道、bundle 构建（lib/client.js）与 HMR 开发流；②最小"记忆工作台"占位 + 一条 host 事件推送到浏览器 | 真实 DSH Web 内可打开占位工作台并收到推送 |
| M0 | 双入口 + 只读工作台（注入面+模拟器、持久面、状态面）+ 事件推送 + 跨工作区只读切换 | 真实 DSH 冒烟；双 agent review；门禁全绿 |
| M1 | 意图启动器（⭐ 收藏 + 预填草稿→对话流→工具卡）+ 收据/回链 + 时间线事件接入 | 端到端：草稿→工具卡→收据 可见且可审计；回归 |
| M2 | （专家）purge 干跑确认、整合前后 diff、时间线因果视图深化、"重要"映射 usage | 视反馈 |

## 10. 开放项与风险

- 标题栏第三方槽位是否存在（S0 首查；回退已接受）。
- 浏览器↔host 推送/remote 的第三方注册路径（S0 验证；不可用则评估上游申请或最小自建 channel 的可行性——需上游许可）。
- 时间线"跳到会话历史位置"定位能力（客户端能力，S0 顺带验证；不可用显示文本引用）。
- 上游 rc/alpha 升级对 client module 契约的影响（沿用"每次 DSH 升级重核契约"纪律）。

## 11. 决策记录（2026-09-05）

- 承载：仅嵌入 DSH Web（dsh.client 客户端半侧）。
- 入口：设置页 + 会话标题栏功能入口；标题栏不可用回退 设置页直达 + `/memory` 斜杠。
- 实时性：M0 即事件推送（降级轮询仅作次级路径）。
- 写语义：UI 永不静默写；remember/forget/修正 = 对话草稿 → 模型工具流 → 工具卡 + 收据；⭐ = 两层分离（视图收藏 vs 语义记忆）；无 UI 直删路径。
- 范围：M0 含注入模拟器与跨工作区只读切换；写路径首批 = 意图启动器（M1）。
